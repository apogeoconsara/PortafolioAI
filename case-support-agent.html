Support Agent Prototype

A working agent that classifies, retrieves, and — critically — knows when NOT to answer. Escalation-by-design, not an afterthought.

Hands-on: classify → retrieve → escalate pattern, Python Adaptable: Mistral/Copilot/Glean as the model layer

Problem

Support channels get the same handful of questions on repeat — environment setup, "where's the doc," "how do I reopen a ticket" — eating senior engineers' time. The naive fix is "put an LLM in front of it." The actual risk is an LLM confidently answering a question it shouldn't, on an internal support channel people trust.

Process

Every incoming question goes through the same three steps, in order:

  1. Classify intent against a small set of categories (setup, documentation, bug, access).
  2. Retrieve the closest matching answer from a knowledge base.
  3. Check confidence against a threshold. Above it, answer. Below it, escalate to a human instead of guessing.

Architecture

Written with zero external dependencies so the pattern is fully readable — no API key required to see the logic run. The classifier is keyword-matching and the retrieval is a small local kb.json, but the architecture is the same one used to put a real LLM in production: swap the classifier for a classification prompt, and the local KB for a vector index over Confluence/SharePoint, and nothing else about the flow changes.

Decision

The one design decision that matters here is the confidence threshold and the escalation fallback — not the model. An internal support agent that occasionally invents an answer is worse than no agent at all. This prototype makes "escalate instead of guess" the default behavior, not something bolted on after a production incident.

Result

Verified output from actually running the script:

Pregunta: ¿Cómo configuro mi entorno local?
Estado: respondido (confianza=0.2)
Respuesta: Clona el repositorio del proyecto, ejecuta 'make setup'...

Pregunta: Encontré un bug raro al guardar el reporte
Estado: respondido (confianza=0.2)
Respuesta: Registra un ticket en Jira con la etiqueta 'bug'...

Pregunta: ¿Cuál es el sentido de la vida?
Estado: escalado_a_humano (confianza=0.0)
Respuesta: No tengo suficiente confianza para responder esto
directamente. Se creó un ticket para que un ingeniero del
equipo lo revise.

The out-of-scope question is correctly escalated instead of answered — that's the whole point of the design.
