# Checklist de auditoría de flujo de ingeniería

Duración sugerida: 45 minutos con el Líder de Proyecto + 1-2 ingenieros del equipo.

## 1. Contexto del proyecto
- [ ] ¿Qué entrega el equipo? (producto, servicio, cliente interno/externo)
- [ ] ¿Qué herramientas de gestión usan hoy? (Jira, Confluence, NetSuite, otras)
- [ ] ¿Existen SLAs o métricas de cliente que dependan de este flujo?

## 2. Pruebas
- [ ] ¿Qué pruebas se ejecutan manualmente hoy y con qué frecuencia?
- [ ] ¿Cuánto tiempo toma diseñar casos de prueba nuevos?
- [ ] ¿Cuánto tiempo toma analizar y reportar resultados?

## 3. Reportes
- [ ] ¿Qué reportes se generan (diarios, semanales, de cierre de sprint)?
- [ ] ¿Se redactan desde cero o se copian de una plantilla?
- [ ] ¿Quién los lee y qué decisiones se toman con ellos?

## 4. Diseño
- [ ] ¿Existen checklists o revisiones de diseño repetitivas?
- [ ] ¿Hay documentación que se actualiza manualmente tras cada cambio?

## 5. Señales de "automatizable con IA"
Marcar cada tarea candidata con estos criterios (1 punto cada uno, máximo 3):
- [ ] Es repetitiva y sigue un patrón reconocible (misma estructura cada vez).
- [ ] La entrada y la salida son principalmente texto o datos estructurados.
- [ ] El costo de un error es bajo o fácilmente revisable por un humano antes de publicarse.

## 6. Cierre
- [ ] Priorizar 2-3 tareas con mayor score y mayor horas/mes.
- [ ] Acordar una prueba piloto de 2 semanas con el equipo.
- [ ] Definir cómo se medirá el éxito (horas ahorradas, calidad, satisfacción).
