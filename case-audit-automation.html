Case 01 · Operational Automation

Workflow Audit Framework

A repeatable way to turn "engineers are busy with repetitive work" into a ranked, defensible automation backlog — before recommending a single tool.

Hands-on: Python, CSV scoring Adaptable: Jira/Confluence delivery

Problem

Engineering teams tend to have a real intuition that "we waste time on repetitive stuff," but no ranked, numbers-backed list of what to automate first. Without that, AI adoption conversations turn into whoever pitches the loudest tool getting funded — not the task with the most leverage.

Process

A structured 45-minute audit interview with the Project Leader and 1-2 engineers, walking through testing, reporting and design work, then flagging each task against three objective signals:

  • Is it repetitive — same structure every time?
  • Is the input/output mostly text or structured data?
  • Is the cost of an error low, or easily caught by a human before publishing?

The full interview guide is in checklist_auditoria.md in the repository.

Architecture

Deliberately not an LLM call. auditor.py takes a CSV of tasks (hours per occurrence, occurrences per month, the three yes/no signals above) and computes:

  • Hours/month consumed per task.
  • An automation score (0-3) — one point per objective signal.
  • An estimated savings percentage mapped to that score (10% / 20% / 50% / 80%), reflecting how much human intervention would realistically still be needed at each level.

Decision

The savings percentage is deliberately not a single made-up number — it's tied to an explicit, inspectable rule (score → % savings) instead of a black-box estimate. That means a Project Leader can disagree with one input and see exactly how the output changes, which is what makes this usable in a real prioritization meeting instead of just a slide.

Result

Run against a sample task inventory for an engineering team:

Tarea                                         Horas/mes  Score IA   Ahorro estimado/mes
Clasificar tickets entrantes de soporte            10.0         3           8.0 h (80%)
Generar reporte semanal de avance                   8.0         3           6.4 h (80%)
Ejecutar smoke tests manuales                      12.0         2           6.0 h (50%)
Redactar minuta de reunión de status                4.0         3           3.2 h (80%)
Actualizar documentación técnica tras cada release  6.0         2           3.0 h (50%)
Revisar checklist de diseño                         5.0         2           2.5 h (50%)

This output was generated by actually running the script against the sample data in the repository — not hand-written.

Documentation

The script writes hallazgos.csv, formatted to paste directly as a table into a Confluence page or attach to a Jira ticket as the backing evidence for a prioritized automation initiative — the artifact this produces is meant to leave the auditor's laptop and live in the team's own tools.
